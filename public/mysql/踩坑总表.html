常备踩坑总表

同一个错误撞第二次，说明缺的不是知识，是索引。这一页把散在各章的报错按「卡在哪一层」重新排了一遍：报错原文 → 什么场景下会撞上 → 一句话解法 → 回哪一页看细节。

跨章汇总 · 覆盖 07 章全部页面 更新：2026-11-25 环境：MySQL 8.0

一屏速记出事时先想起这 5 条，再去下面查表

  1. 排查顺序就四层：能不能连上 → 能不能通过认证 → 语句能不能执行 → 结果对不对。上一层没过，就别去查下一层。
  2. 真正常撞的就几个：1045 密码或来源主机不对、1049 是 -p 后面多了空格、1290 是路径不在信任目录、1146 是表名或库没选对。
  3. 最危险的不是报错，是不报错：漏加 --routines、把 TABLE_ROWS 当真实行数、ping 返回 0、mysqlshow 只列出几个库——四个都是「看起来成功」。
  4. 看报错先看括号里的 SQLSTATE，再读后半句英文：MySQL 的消息是「现象 + 原因」结构，真正的原因通常在冒号后面。
  5. 同一条命令换到 Windows cmd 要多想一步：引号、行尾分号、> 重定向的编码，都会变成新坑。

先判断卡在哪一层

A　连不上：网络与服务

报错原文什么场景会撞上一句话解法出处
ERROR 2002 (HY000): Can't connect through socket '/tmp/mysql.sock' (2) 本机连接走 socket，但服务没起，或客户端和服务端找的 socket 路径不一致 先 mysqladmin ping 看服务活着没；再 mysql_config --socket 核对客户端用的路径 7.2.1
ERROR 2003 (HY000): Can't connect to MySQL server on '127.0.0.1' (10061) 走 TCP，但 3306 没在监听，或被防火墙/安全组挡住 查 bind-address 与 port；telnet 127.0.0.1 3306 验证端口通不通 7.2.1
ERROR 1130 (HY000): Host '192.168.1.20' is not allowed to connect to this MySQL server 账号在这个来源主机上没有授权记录，被直接挡在认证之前 建 'user'@'192.168.1.20'；'%' 能用但要清楚代价 7.1
ERROR 1129 (HY000): Host '192.168.1.20' is blocked because of many connection errors 该 IP 连续握手失败次数超过 max_connect_errors（默认 100），被临时拉黑 mysqladmin flush-hosts 解封，再查它为什么一直失败（多半是密码错在重试） 7.2.2
connect to server at 'localhost' failed mysqladmin / mysql 都报这句，服务确实没起来 与 2002 同类：先 systemctl status mysqld，再看错误日志 7.2.2

B　连上了但被拒：认证与权限

报错原文什么场景会撞上一句话解法出处
ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: YES) 密码错、账号不存在，或实际匹配到了另一条 host 记录 先分清走的是 localhost 还是 127.0.0.1——这是两条独立记录；再 SELECT user,host FROM mysql.user 7.2.1
ERROR 1049 (42000): Unknown database '123456' -p 与密码之间多了空格，密码被当成库名 写成 -p123456，中间不留空格 7.2.1
ERROR 1410 (42000): You are not allowed to create a user with GRANT 8.0 起 GRANT 不再隐式建用户，老教程的写法直接失效 先 CREATE USER，再 GRANT 7.1
ERROR 1227 (42000): Access denied; you need ... the SYSTEM_VARIABLES_ADMIN privilege(s) 8.0 把 SUPER 拆成了一堆细粒度动态权限，老账号不够用了 授具体的那个动态权限，别图省事直接给 SUPER 7.1
ERROR 3554 (HY000): Access to data dictionary table 'mysql.xxx' is rejected 直接 SELECT 数据字典隐藏表 改查 information_schema，或走 SHOW 7.1

C　语句执行失败：路径、对象、模式

报错原文什么场景会撞上一句话解法出处
ERROR 1290 (HY000): The MySQL server is running with the --secure-file-priv option so it cannot execute this statement mysqldump -T 目录 的目录不在信任目录里；文件是服务端写的 换到 secure_file_priv 目录下；或改用 mysqldump > 文件（客户端写，不受限） 7.2.5
ERROR 1238 (HY000): Variable 'secure_file_priv' is a read only variable 想在会话里 SET 掉这个限制 它只能改 my.cnf 后重启；不想重启就用客户端写文件绕开 7.2.5
ERROR 3950 (42000): Loading local data is disabled mysqlimport --local，但服务端 local_infile=OFF（8.0 默认） SET GLOBAL local_infile=ON，要长期生效就写进 my.cnf 7.2.6
ERROR 1146 (42S02): Table 'test.city' doesn't exist mysqlimport 的表名取文件名，而且它从不建表 先 CREATE TABLE city，并确认库选对了 7.2.6
ERROR 1175 (HY000): You are using safe update mode 客户端开了 --safe-updates，UPDATE/DELETE 的 WHERE 没带主键或索引 WHERE 里带上主键；或临时 SET SQL_SAFE_UPDATES=0，但别在线上图省事 7.2.1
ERROR 1046 (3D000): No database selected 单库 dump 文件里既没有 CREATE DATABASE 也没有 USE 导入时指定库：mysql 库名 < dump.sql；或备份时改用 -B 7.2.5

D　不报错，但结果是错的

这一组最贵：命令返回 0、屏幕上一片绿，你以为成了。它们不会进任何错误日志，只能靠「知道有这么回事」提前防。

表面现象真实原因怎么确认 / 怎么防出处
导入成功，但业务报「存储过程不存在」 备份漏了 --routines --triggers --events，这三类对象默认不导 备份命令里补上；恢复后 SELECT COUNT(*) FROM information_schema.ROUTINES 对数 7.2.5
TABLE_ROWS 显示 1200，实际 38000 InnoDB 的 TABLE_ROWS 是采样估算，还被 information_schema_stats_expiry 缓存（默认 86400 秒） 要精确就 SELECT COUNT(*)；或先 SET SESSION information_schema_stats_expiry=0 7.1
mysqladmin ping 返回 0，以为账号没问题 ping 证明的是「服务端能应答」，认证被拒也返回 0 验证账号用 mysql -e "SELECT 1" 看退出码 7.2.2
mysqlshow 只列出 3 个库，以为实例就这 3 个 输出按当前账号的权限过滤，没权限的对象根本不出现 不能当清点工具；全量统计查 information_schema.SCHEMATA 7.2.4
