07MySQL 管理

这一章管的是「数据库之外」：MySQL 自带的四个系统库，和服务器端那批命令行工具。每个工具单独一页，从下面的工具地图进去。

进阶篇 · 第 7 章 更新：2026-11-25 环境：MySQL 8.0

7.1 系统数据库

装完就有四个库：mysql、information_schema、performance_schema、sys。它们不是四个平级的数据库，而是四层不同的东西——一层存真相，一层做翻译，一层记运行时，一层把前两层包成人话。这一节拆成了独立页面，内容比较多：

存数据

mysql

37 张可见系统表：权限 10、复制 8、优化器 4、日志 2、帮助 4、时区 5、其他 4。另有约 30 张隐藏的数据字典表。
查结构

information_schema

库、表、列、索引、触发器、视图、存储过程的元数据。8.0 里是数据字典的窗口，元数据本体反而不让直读。
查运行

performance_schema / sys

前者是内存里的原始事件（皮秒、重启清零），后者把它包成 sys.session 这类能直接读的视图。
完整的 7.1 在独立页

→ 打开「7.1 系统数据库」。里面有四库依赖图、37 张表的分组图、权限四层收窄图，以及几个实际会咬人的点：mysql.tables 直查报 3554、TABLE_ROWS 缓存 24 小时、时区表默认是空的、复制表名没跟着 source/replica 改名。

一句话边界：只有 mysql 需要备份，另外三个是启动时重建出来的。所以「只备份业务库」会连账号一起丢掉。

7.2 常用客户端工具

按用途分三组。蓝色实心的是已经整理好的，点名字进去看；灰色虚线的是还没写，等课程讲到那里再补。

工具作用一句话笔记
mysql命令行客户端，登录、跑 SQL、-e 批处理、source 导入脚本平时敲的就是它 已整理 →
mysqladmin看状态、探活、刷日志、关服务、建/删库不进 SQL 就能干的活 已整理 →
mysqldump逻辑备份，单线程，最通用备份工具的主力 已整理 →
mysqlbinlog把二进制日志翻译成可读 SQL，做按时间点恢复binlog 的翻译器 已整理 →
mysqlshow一条命令看库 / 表 / 列 / 索引，SHOW 语句的壳不看会话就能查结构 已整理 →
mysqlimport把文本数据文件灌进表里；source 导 SQL 脚本也记在这一页恢复时的搬运工 已整理 →
mysqlpumpmysqldump 的并行版，8.0.34 弃用、8.4 已移除别在新版本上依赖它 旁注
两个工具共用一个限制：secure_file_priv

mysqldump -T 写文件、mysqlimport（不带 --local）读文件，动作都在服务端完成，所以路径必须落在 secure_file_priv 指定的目录里，否则报 ERROR 1290。这不是「权限没给」，是「这个目录不被信任」。三种取值、各平台默认值和改法，见 mysqldump · secure_file_priv 信任目录。

这一章的阅读方式

每个工具单独一个 HTML 文件，命名 07-NN-工具名.html，从本页和总目录都能跳进去。目前完成六个：mysql（客户端）、mysqladmin（状态与关停）、mysqlbinlog（日志解析与 PITR）、mysqlshow（对象查找）、mysqldump（备份）、mysqlimport / source（导入恢复），其余按课程进度补。
