7.2.1mysql 客户端

课程里第一句就说清楚了：这里的 mysql 不是 MySQL 服务，是客户端工具。这句话值得单独拎出来讲，因为接下来所有命令都建立在这个前提上——你敲的每一条，都是发给另一个进程的请求。

进阶篇 · 7.2.1 更新：2026-11-25 环境：MySQL 8.0

一屏速记合上笔记，这 5 条要能自己说出来

  1. mysql 是客户端，服务端是 mysqld。客户端只做三件事：连上去、把 SQL 发过去、把结果排版。
  2. -p 和密码之间不能有空格：写 -p123456。写成 -p 123456 会让它以为你没给密码，而 123456 被当成库名，报 ERROR 1049。
  3. -h localhost 走 Unix socket（Windows 走命名管道 / 共享内存），-h 127.0.0.1 走 TCP。在权限表里这是两条独立记录，'root'@'localhost' 连不上 127.0.0.1。
  4. -e "SQL" 执行完立即退出，是脚本的入口；再配 -N（去表头）+ -B（制表符分隔、无边框），输出才能被 while read 消费。
  5. mysql_config_editor 生成的 .mylogin.cnf 是 obfuscated 混淆，不是加密，能还原出明文密码，别当保险箱用。

1. 它不是 MySQL 服务

装完 MySQL 会得到好几个可执行文件，名字都带 mysql，但角色完全不同。分不清就会犯两类错：以为关了客户端服务就停了，或者以为客户端卡住是数据库挂了。

怎么确认自己在跟谁打交道

SELECT VERSION(); 查的是服务端版本；mysql --version 查的是客户端版本。两者可以不同——客户端 8.0 连 5.7 服务端是允许的，反过来会受限。

2. 语法：一条命令四件事

截图里的语法是 mysql [options] [database]。方括号表示可选，[database] 是位置参数——不带前缀的那个词，就是登录后默认进入的库，等价于 -D db01。

选项长选项作用不写时
-u--user=name指定用户名用当前系统登录名
-p--password[=name]指定密码提示输入
-h--host=name服务器 IP 或域名localhost
-P--port=#连接端口（大写）3306
-e--execute=name执行 SQL 后退出进交互界面
-D--database=name指定默认库，等价于位置参数无默认库
-S--socket=path指定 socket 文件按安装路径找默认值
-A--no-auto-rehash登录时不预读表名做补全预读，大库会很慢
-U--safe-updates拒绝不带键条件的 UPDATE/DELETE允许，危险
-P 和 -p 是两个完全不同的东西

大写 -P 是端口，小写 -p 是密码。远程连非 3306 端口时写成 -p 3306，结果不是连不上，而是「把 3306 当密码，再把下一个词当库名」——报错信息和真正的原因完全对不上。

3. -p 的三种写法，只有一种不出事

这是初学者最常见的翻车点，而且它的报错方式极具误导性：你会看到 Unknown database，而不是「密码错误」。

更阴的情况：那个「密码」恰好是真实存在的库名

如果你敲的是 mysql -uroot -p itcast，而 itcast 这个库真的存在，就不会报 1049——它会提示你输密码，然后正常登录进 itcast 库。你完全察觉不到自己少打了一个空格，直到某天在别的机器上同样的命令突然报错。

规律：-p 只在紧贴字符时才算「带值」。空一格，它就退化成一个「请提示我输密码」的开关。

那 -p123456 能不能用？能，但不该用。明文密码会留在三个地方：~/.bash_history、ps aux 的进程列表、以及脚本文件本身。MySQL 从 5.6 起会直接警告：

shellmysql: [Warning] Using a password on the command line interface can be insecure.

官方给的替代方案是 mysql_config_editor，把连接信息写进混淆过的 .mylogin.cnf，之后只用一个名字登录：

shell# 存一组连接信息（只需执行一次，会提示输入密码）
mysql_config_editor set --login-path=local \
  --host=127.0.0.1 --port=3306 --user=root --password

# 看存了哪些（密码显示为 *****）
mysql_config_editor print --all

# 之后这样登录，命令行里不再出现密码
mysql --login-path=local db01

# 备份脚本里同样能用
mysqldump --login-path=local itcast > itcast.sql
别把它当保险箱

官方用词是 obfuscated（混淆），不是加密。文件位置：Linux/macOS 在当前用户家目录，Windows 在 %APPDATA%\MySQL。它的真实价值是把密码从命令行、脚本和历史记录里移走，而不是「即使文件泄露也安全」。

4. -h localhost 不是 -h 127.0.0.1

这两个看起来一样，实际上走的是两条完全不同的路。MySQL 里 localhost 不是一个 IP，是一个暗号：走本地 socket 文件。

典型症状：本地能连，换成本机 IP 就连不上

mysql -uroot -p 正常，改成 mysql -h127.0.0.1 -uroot -p 报 ERROR 1045 Access denied。原因不是密码错，是 'root'@'localhost' 这条记录匹配不到走 TCP 的连接。要么给 'root'@'127.0.0.1' 授权，要么用 -S 指定 socket。

用 status;（或 \s）能在交互界面里看到当前走的是哪条：Connection: Localhost via UNIX socket 或 Connection: 127.0.0.1 via TCP/IP。

5. -e 与输出格式

截图里说 -e 适合批处理脚本，这话只说了一半。真正让它在脚本里好用的是输出格式选项——执行完就退出，但结果怎么打印，取决于你怎么控制 stdout。

shell# 课程示例：进库、跑一条、退出
mysql -uroot -p123456 db01 -e "select * from stu"

# 脚本里取值：去掉表头、不要边框，结果直接进变量
CNT=$(mysql -uroot -p -N -B db01 -e "select count(*) from stu")

# 导出 CSV（tab 换逗号）
mysql -uroot -p -N -B db01 -e "select * from stu" | tr '\t' ',' > stu.csv

# 一次跑多条语句，用分号隔开
mysql -uroot -p db01 -e "show tables; select now();"

# 直接执行 .sql 脚本，不进交互界面
mysql -uroot -p db01 < init.sql

# 大表查询不想在客户端攒内存
mysql -uroot -p -q db01 -e "select * from big_table" > big.txt
三个让它更好用的开关

-A：登录时默认会预读所有库的表名做补全，几百张表的库能卡好几秒。加 -A 跳过。

-U：--safe-updates，拒绝没有用到键的 UPDATE/DELETE，报 ERROR 1175。远程连生产库时建议默认带上。

--default-character-set=utf8mb4：客户端字符集跟着系统 locale 走，Windows 上中文乱码十有八九是这里，服务端默认 utf8mb4 但客户端没跟上。

6. 进去之后的命令

登录后提示符变成 mysql>，这时的规则和 shell 不一样：语句以分号或 \G 结束才会执行，只敲回车不会跑。

命令作用什么时候用
\s / status看当前连接信息：版本、当前库、字符集、socket 或 TCP怀疑自己连错实例、查字符集
\G把当前语句改成竖排输出列太多导致换行错乱，SHOW CREATE TABLE
\c放弃正在输入的语句敲错了、少了个引号卡住
\q / exit退出客户端—
\h / help查看帮助，help 'SELECT' 查语法忘了某个语句怎么写
source 文件执行本机 SQL 文件导入备份，见 mysqlimport / source
tee 文件把本次会话的输出同时写进文件记录一次排查过程
pager less结果用分页器显示结果集很长，想翻页看
 
sql-- 别只看表名，看连接到底走哪条路、字符集对不对
status;

-- 一行太长看不清，换成竖排
SHOW CREATE TABLE emp\G

-- 查看某条语句的官方语法
HELP 'SELECT';

7. 连不上怎么查

客户端报的错其实已经把方向指出来了，只是错误码不好记。按这个表对照，能省掉大部分瞎试：

报错真实含义下一步查什么
ERROR 2003 Can't connect to MySQL serverTCP 连不上：服务没起、端口不对、防火墙拦了netstat -ano | findstr 3306，或 mysqladmin -uroot -p status
ERROR 2002 Can't connect through socketsocket 文件不存在或路径不对（仅 Unix）mysql_config --socket 看服务端用的是哪个
ERROR 1045 Access denied账号、密码、来源主机三者之一对不上SELECT user, host FROM mysql.user；注意 using password: YES/NO
ERROR 1049 Unknown database 'xxx'库名拼错，或 -p 后面多打了空格先看命令里有没有 -p 密码
ERROR 1046 No database selected没指定库，语句里也没写库名加位置参数，或先 USE db01;
ERROR 1175 safe update mode带了 -U，而 UPDATE/DELETE 没用到键补 WHERE 主键 = ?，而不是关掉保护
ERROR 1130 Host is not allowed该来源主机根本没有被任何账号允许建账号时 Host 写了 localhost，远程自然进不来
这一页要带走的三句

1. mysql 是客户端；mysqld 才是服务，数据只在服务那边。
2. -p 只有紧贴密码才算「带值」，空一格就把下一个词当库名——报的是 1049，不是密码错。
3. localhost 走 socket，127.0.0.1 走 TCP，在权限表里是两个账号。

自测三问先自己答一遍，再点开对答案

Q1mysql -uroot -p 123456 报 ERROR 1049 (42000): Unknown database '123456'，密码没错，为什么？

-p 与密码之间多了空格。有空格时它认为你没给密码（转去提示输入或按空密码处理），后面的 123456 就被当成要连接的库名。正确写法是 -p123456。

Q2同一台机器上 -h localhost 能进，改成 -h 127.0.0.1 就 Access denied，为什么？

两者走的连接方式不同：localhost 走 socket，匹配 'root'@'localhost'；127.0.0.1 走 TCP，匹配 'root'@'127.0.0.1'。这是账号表里的两条不同记录，只建了前者就会出现这种现象。

Q3脚本要遍历所有库名，mysql 命令该怎么写、为什么这么写？

mysql -N -B -e "SHOW DATABASES"。-B 进批处理模式（制表符分隔、不加边框与填充），-N 去掉列名行，输出才是一行一个库名，可以直接喂给 while read db。
