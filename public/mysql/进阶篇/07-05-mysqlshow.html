7.2.4mysqlshow

截图那句定义说得很准：客户端对象查找工具，用来快速看有哪些库、库里有哪些表、表里有哪些列和索引。它比前四个工具都简单，因为它没有自己的逻辑——官方文档原话是「a command-line interface to several SQL SHOW statements」，一层把参数翻译成 SHOW 的壳。正因为它这么薄，两个东西才值得记：--count 的代价，和「不是所有对象都会显示出来」。

进阶篇 · 7.2.4 更新：2026-11-25 环境：MySQL 8.0

一屏速记合上笔记，这 5 条要能自己说出来

  1. 它自己的查询能力是零：官方定位就是若干 SQL SHOW 语句的命令行封装，mysqlshow db 基本等于 SHOW TABLES FROM db。
  2. 四个位置参数是下钻路径：[db [table [column]]]，给得越深返回越细。
  3. --count 是真的逐表 SELECT COUNT(*)，官方明说对 non-MyISAM 表很慢；不带库名就扫全实例，连系统库和视图一起真查。
  4. -i / --status 走 SHOW TABLE STATUS，行数是 InnoDB 的估算值，和 --count 的数字对不上很正常。
  5. 输出经过权限过滤：只列你有权限的对象。「只看到 3 个库」不等于「服务器上只有 3 个库」，别拿它清点家底。

1. 它只是 SHOW 语句的一层壳

先把这个定位钉死，后面所有现象都能推出来：它不产生任何新信息。你在 mysql 里敲 SHOW TABLES 能看到的，它才看得到；SHOW 看不到的，它也看不到。

所以它唯一的价值是省掉一次交互：不用登录进 mysql、不用写分号、不用 USE，一条命令出结果，能直接塞进 shell 脚本或定时任务。

2. 四个位置参数是下钻路径

语法里那串方括号 [db_name [tbl_name [col_name]]] 容易读成「可选过滤条件」，其实它是下钻路径：给到第几层，就停在第几层，不会再往下。

写法看到什么等价的 SQL
mysqlshow库名列表，单列SHOW DATABASES
mysqlshow test库里的表名，单列SHOW TABLES FROM test
mysqlshow test book9 列：Field / Type / Collation / Null / Key / Default / Extra / Privileges / CommentSHOW FULL COLUMNS FROM test.book
mysqlshow test book id只列出匹配 id 的列SHOW FULL COLUMNS ... LIKE 'id'
mysqlshow test book id -k该列上的索引SHOW INDEX ... WHERE Column_name LIKE 'id'
第二列那 9 个字段值得看一眼

它们不是 mysqlshow 自己算的，是 SHOW FULL COLUMNS 的原始输出。注意最后一列 Privileges——它会写着 select,insert,update,references 这种你在这个列上拥有的权限。这一列在 DESC 里是看不到的，因为 DESC 用的是 SHOW COLUMNS（非 FULL）。

3. 截图给的两个选项

截图只列了 --count 和 -i，这两个确实是最常用的。但它们的取数方式完全不同，这是这一节最要紧的一点。

选项短形式背后发的语句说明
--count无 每张表一次 SELECT COUNT(*)，库级再把各表加起来 输出多出 Rows / Total Rows 列
--status-i SHOW TABLE STATUS 引擎、行数估算、数据与索引大小、创建/更新时间
--keys-k SHOW INDEX 表上的索引；给了 col_name 就只列该列的
--show-table-type-t SHOW FULL TABLES 多一列 Type：BASE TABLE 或 VIEW
--verbose-v — 可叠加，把连接过程也打出来，排查连不上时有用
--count 没有短选项

官方选项表里它只有长形式，写成 -c 会直接报 unknown option。这一点和 -i、-k、-t 不一样，很容易顺手写错。

4. --count 的真实代价

截图说「数据库及表的统计信息（数据库，表均可以不指定）」，这句话本身没错。但「不指定库」时它做的事情被这句话盖住了：它会把实例里每个库的每张表都 COUNT(*) 一遍。

官方文档对 --count 只有一句说明，最后半句是关键：「Show the number of rows per table. This can be slow for non-MyISAM tables.」——MyISAM 存了精确行数，所以快；InnoDB 没有，只能真数。

它的输出有三种形态，取决于你给到第几层。这个差异也值得记，因为很多人以为「--count 就是多一列行数」：

shell# ① 不给库名：一张库级汇总表
mysqlshow -uroot -p2143 --count
+--------------------+--------+------------+
| Databases          | Tables | Total Rows |
+--------------------+--------+------------+
| information_schema |     79 |      24620 |
| mysql              |     37 |       5343 |
| performance_schema |     87 |     262769 |
| sys                |    101 |       7477 |
| test               |      2 |          3 |
+--------------------+--------+------------+

# ② 给库名：一张表级汇总表（多出 Columns 列）
mysqlshow -uroot -p2143 test --count
Database: test
+-------+---------+------------+
| Tables | Columns | Total Rows |
+-------+---------+------------+
| book  |       3 |          2 |
| emp   |       8 |         17 |
+-------+---------+------------+

# ③ 给到表：头顶多一行 Rows，下面照常列字段
mysqlshow -uroot -p2143 test book --count
Database: test
Table: book
Rows: 2
+-------+-------------+------+-----+---------+----------------+
| Field | Type        | Null | Key | Default | Extra          |
+-------+-------------+------+-----+---------+----------------+
| id    | int         | NO   | PRI | NULL    | auto_increment |
| name  | varchar(50) | YES  |     | NULL    |                |
+-------+-------------+------+-----+---------+----------------+
只想估个规模，用 -i 就够了

mysqlshow -uroot -p2143 test -i 走的是 SHOW TABLE STATUS，毫秒级返回。它的 Rows 对 InnoDB 是估算值，官方说可能和实际差 40%–50%，但看「哪张表最大」这种相对比较完全够用。要精确数字，再到具体表上单独 COUNT(*)。

5. 你看到的不是全部

官方文档里有一句很容易被跳过的话：「The output displays only the names of those databases, tables, or columns for which you have some privileges.」

意思是它输出的是「你能看到的那部分」，不是「服务器上存在的」。普通账号敲 mysqlshow，很可能只列出两三个库，看起来像是刚装好的空实例，其实剩下的库它只是不显示。

6. 只有最后一个参数算模式

这是个很细、但一定会碰到的规则，官方文档没有单独强调，只在通配符那段话里带出来：位置参数里只有最后一个会被当成 LIKE 模式，前面的都按字面名查。

配套的行为是：* 和 ? 会被转成 SQL 的 % 和 _。也就是说，下划线在你写模式的那个位置上是通配符，不是字面下划线。

顺带记一个 shell 层的坑：在 bash 里写 mysqlshow test t*，t* 会先被 shell 当文件名展开（当前目录有匹配文件时就会变成一串文件名），根本到不了 mysqlshow。加引号即可：

shell# bash 里要引号，Windows cmd 里不用
mysqlshow -uroot -p2143 test 't*'

# 下划线转义：Unix shell 下写两个反斜杠更保险
mysqlshow -uroot -p2143 'my\_db'

# 官方给的兜底写法：末尾补 %，让前一个参数退回字面名
mysqlshow -uroot -p2143 my_db my_table %

7. 什么时候用它，什么时候别用

它最大的好处是「一条命令、不用进会话」；最大的局限也在同一处——输出是画出来的 ASCII 表格，不是结果集。要拿去做统计或进脚本，它并不合适。

mysqlshow进会话敲 SHOW查 information_schema
要不要登录会话不要，一条命令要要
输出形态ASCII 表格，给人看结果集结果集
能否 WHERE / 聚合 / JOIN不能不能能
塞进脚本得 grep / awk 硬解不方便可直接用
典型场景临时确认一下结构会话里随手看巡检、报表、统计大表
 
sql-- 想按大小排、按行数排，mysqlshow 做不到，得回到 SQL
SELECT table_name,
       table_rows,
       ROUND(data_length / 1024 / 1024, 1) AS data_mb,
       engine
FROM information_schema.tables
WHERE table_schema = 'test'
ORDER BY data_length DESC;
现象原因怎么做
报 unknown option '-c' --count 没有短形式 写全 --count
报 Unknown database 库名写错，或这个账号连这个库都看不到 先不带参数跑一次，看它到底能看到哪些库
输出比预期少很多库 输出经过权限过滤 换高权限账号复核，别据此判断「服务器上只有这些」
列出了一堆没想匹配的表 最后一个参数被当模式，里面的 _ 是通配符 末尾补一个 %，或用引号加反斜杠转义
命令卡住很久没返回 --count 在逐表 COUNT(*)，碰上大表就在扫 Ctrl+C 中断；要估算改用 -i
Rows 和实际条数对不上 -i 的 Rows 是 InnoDB 统计估算 要精确就 SELECT COUNT(*)；或直接用 --count
这一页要带走的三句

1. 它只是 SHOW 语句的一层壳，四个位置参数是下钻路径（库 → 表 → 列 → 索引），给到哪层停在哪层。
2. --count 是真的逐表数，不带库名就是整实例扫一遍，连系统库和视图都不放过；只想估规模用 -i。
3. 输出只包含你有权限的对象，且只有最后一个参数算模式——这两条决定了它不能当清点工具用。

自测三问先自己答一遍，再点开对答案

Q1mysqlshow --count 和 mysqlshow -i 打出来的行数差很多，哪个是真的？

--count 是真的 SELECT COUNT(*)；-i 走 SHOW TABLE STATUS，InnoDB 返回采样估算，差 40%~50% 都正常。要精确只能 COUNT。

Q2mysqlshow itcast 'user_log' 明明有这张表却匹配不到，为什么？

只有最后一个位置参数会被当成 LIKE 模式，而 _ 在 LIKE 里是「任意一个字符」。写成 'user\_log' 转义，或按官方建议在末尾补 %：'user_log%'，让表名退回字面匹配。

Q3想用它统计「这台实例一共多少张表」，结果少了一大半，为什么？

输出按当前账号的权限过滤，没权限的库和表根本不会出现。要全量统计，得查 information_schema.TABLES。
