7.2.2mysqladmin

截图第一句是「一个执行管理操作的客户端程序」。这句话里最要紧的是「管理」两个字：它不跑 SELECT，也不进交互界面，每次只连上去干一件事然后断开。所以它的所有奇怪行为——没有当前库、不用 quit、退出码当返回值用——都是从这个前提推出来的。

进阶篇 · 7.2.2 更新：2026-11-25 环境：MySQL 8.0

一屏速记合上笔记，这 5 条要能自己说出来

  1. 命令是位置参数，不是选项：mysqladmin status ping 会连着执行两个动作，一次连接做完多件事。
  2. 二十多条命令分四组：探活（ping / status / processlist）、改状态（shutdown / reload / refresh / flush-*）、建删库（create / drop）、复制（start / stop-replica）。
  3. ping 只证明「服务端能应答」：认证失败时退出码仍然是 0，不能拿它判断账号密码对不对。
  4. status 里的 Queries per second avg = Questions ÷ Uptime，是开机以来的平均值，不是此刻的 QPS。
  5. 8.0 的变化：debug 已移除、password 已弃用、start/stop-slave 改名为 start/stop-replica；FLUSH HOSTS 这条 SQL 在 8.4 移除，但 mysqladmin flush-hosts 还在。

1. 一次连接只干一件事

mysql 和 mysqladmin 都是客户端，但工作模式相反：前者开一次连接后一直保持会话，后者每条命令单独连一次。这不是实现细节，而是它会带来一串后果——没有「当前库」，USE 对它无效；不保存会话变量；也不需要 quit。

mysqlmysqladmin
典型用途跑 SQL、看数据、导脚本看状态、刷日志、关服务、建/删库
连接保持，直到 quit每条命令独立一次
位置参数库名命令名（status、ping…）
结果怎么用人眼看，或管道给脚本打印文本 + 退出码
为什么「关服务」要用它而不是 systemctl stop

本机运维用 systemctl 更规范；mysqladmin shutdown 的价值在远程和没有系统权限的场景——只要有 SHUTDOWN 权限的账号，从任何一台能连到 3306 的机器都能正常停库，不用登服务器。它走的是 MySQL 自己的停机流程：等当前语句结束、刷盘、关闭连接，不是直接杀进程。

2. 语法：命令是位置参数

截图语法是 mysqladmin [options] command [command-arg] [command [command-arg]] ...。最后这段要注意：一条命令行可以挂多个命令，它们共用一次连接，按顺序执行。

-i 秒 / --sleep每隔 N 秒重复执行命令盯状态、做轮询
-c 次数 / --count配合 -i，重复几次采 5 个点就退出，不写死循环
-r / --relative只对 extended-status 有效，显示与上次的差值看每秒增长量，而不是累计值

4. status 那八个字段

截图只写了「Gives a short status message from the server」，实际这一行信息量不小。八个字段里有一个被中文教程广泛讲错，就是最后那个 Queries per second avg。

这八个字段都是 SHOW GLOBAL STATUS 的子集。要更细，直接查那几个变量：

sql-- 连接与并发
SHOW GLOBAL STATUS LIKE 'Threads_%';
SHOW GLOBAL STATUS LIKE 'Max_used_connections';

-- 连接失败（握手阶段就断的）
SHOW GLOBAL STATUS LIKE 'Aborted_%';

-- 慢查询与全表扫描
SHOW GLOBAL STATUS LIKE 'Slow_queries';
SHOW GLOBAL STATUS LIKE 'Select_full_join';

5. ping 的退出码，和你想的不一样

ping 是脚本里最常用的命令，因为它的退出码就是结论。但官方文档里有一句很反直觉的话：即使用户名密码错了，只要服务在，它照样返回 0。理由是「服务活着但拒绝了你」和「服务根本不在了」是两件事。

shell# 课程示例：探活
mysqladmin -uroot -p ping

# 脚本里用：静默 + 只看退出码
if mysqladmin -uroot -p"$PASS" -h127.0.0.1 --silent ping; then
  echo "mysqld 在"
else
  echo "mysqld 不在"
fi

# 每 2 秒采一次状态，共 5 次，结果落文件
mysqladmin -uroot -p -i 2 -c 5 status >> status.log

# 看“每秒增长量”而不是累计值，必须用 extended-status
mysqladmin -uroot -p -i 2 -r extended-status | grep -E 'Queries|Com_select|Com_insert'

# 从别的机器关掉这台库
mysqladmin -h192.168.1.10 -uroot -p shutdown
-i 不加 -c 就是死循环

官方文档写得很明确：只给 --sleep 不给 --count，会一直执行到被中断。放在 crontab 或 CI 里忘了加 -c，会留下一个永远不退出的进程。

-r 只对 extended-status 起作用，对 status 无效——这也是为什么盯增长量时要换命令。

6. create / drop / kill

这三个是真正会改东西的。它们的共同点是：参数不是选项，而是紧跟其后的位置参数，所以写错一个词，动作就落到别处了。

shell# 建库 / 删库（课程示例）
mysqladmin -uroot -p123456 create test01
mysqladmin -uroot -p123456 drop test01

# 删库不想被问，加 -f
mysqladmin -uroot -p -f drop test01

# 杀线程：ID 用逗号隔开，不能有空格
mysqladmin -uroot -p processlist
mysqladmin -uroot -p kill 12,15
create databasename 里的 databasename 是占位符

截图里的帮助文本写作 create databasename Create a new database，那个词是「库名」的占位符，不是关键字。真敲 mysqladmin create database，MySQL 会老老实实建一个名字叫 database 的库，然后你对着一个空库发呆。正确写法是直接跟库名：mysqladmin create test01。

同理 drop databasename，写成 drop database 就是去删那个叫 database 的库。

Windows 的 cmd 里，分号和单引号都会变成名字的一部分

课程示例写的是 mysqladmin -uroot -p123456 drop 'test01';。在 bash 和 PowerShell 里，分号是语句分隔符、单引号会被剥掉，没问题；但在 cmd.exe 里，分号不是分隔符、单引号也不剥，实际传给工具的是 'test01';，于是报库不存在。

Windows 上照这个写：mysqladmin -uroot -p123456 drop test01，不加引号也不加分号。

7. 截图里四条要打补丁

课程录在 8.0 早期，帮助输出里这几行现在还印得出来，但照抄会出问题。单独拎出来标注，免得以后翻笔记时踩旧坑。

sql-- 改密码：8.0 的正确写法，能指定任意账号
ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';

-- 顺手清掉主机缓存里被拉黑的 IP（看谁被拉黑）
SELECT ip, host, sum_connect_errors
FROM performance_schema.host_cache
ORDER BY sum_connect_errors DESC;
顺便说清 flush-hosts 的处境

它自己没被弃用，但它对应的 SQL 语句 FLUSH HOSTS 在 8.0.23 已弃用、8.4 已移除。所以在 8.4 上要清主机缓存，要么用 mysqladmin flush-hosts，要么 TRUNCATE TABLE performance_schema.host_cache。这条恰好和 mysqlpump 是同一种情况：客户端命令还在，SQL 语句先没了。

8. 报错对照

输出真实原因下一步
connect to server at 'localhost' failed服务没起、端口不对、socket 路径不对systemctl status mysqld；再 mysqladmin ping
Access denied for user ...账号、密码、来源主机之一不对注意 ping 此时仍返回 0，别被迷惑
Access denied; you need ... SHUTDOWN privilege(s)账号缺 SHUTDOWNGRANT SHUTDOWN ON *.* TO ...，或改用 systemctl stop
You are not owner of thread N杀的是别人的线程，缺 CONNECTION_ADMIN换高权限账号；确认 ID 没抄错
ERROR 1129 Host is blocked（连接阶段）该 IP 连续握手失败超过 max_connect_errors（默认 100）mysqladmin flush-hosts 解封，再查为什么一直失败
mysqladmin: unknown command 'xxx'命令拼错，或写成了 --status命令不带横杠；用 mysqladmin --help 对一遍
Unknown database 'test01;'cmd 里把分号拼进了库名去掉末尾分号和单引号
这一页要带走的三句

1. 它是「一次连接干一件事」的管理客户端：没有当前库，也不用 quit。
2. status 的 QPS avg 是 Questions ÷ Uptime，不是查询耗时；耗时看慢日志。
3. ping 返回 0 只说明服务活着，密码错了也返回 0；debug、password、slave-* 三条别照抄。

自测三问先自己答一遍，再点开对答案

Q1mysqladmin -uroot -pwrong ping; echo $? 输出 0，说明密码是对的吗？

不能说明。只要服务端能应答，ping 就返回 0，认证被拒也算「活着」。要验证账号能不能用，改用 mysql -e "SELECT 1" 看退出码。

Q2Queries per second avg: 3.421 能当当前 QPS 用吗？

不能。它是 Questions ÷ Uptime 的历史平均值，开机越久被稀释得越厉害。要看实时压力，两次采样 SHOW GLOBAL STATUS LIKE 'Questions' 求差，再除以间隔秒数。

Q3想安全停库，mysqladmin shutdown 和自己 kill 掉进程有什么区别？

shutdown 走正常关闭流程：停止接受新连接、刷脏页、写完 redo、更新统计，InnoDB 干净退出。直接杀进程相当于断电，下次启动要做 crash recovery，极端情况会丢未刷盘的事务。
