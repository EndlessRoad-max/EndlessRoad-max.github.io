7.2.6mysqlimport 与 source

两个「往回灌」的工具：mysqlimport 灌的是 文本数据文件（mysqldump -T 的产物之一），source 跑的是 SQL 脚本。分不清这两者，恢复时就会拿错命令。

进阶篇 · 7.2 常用客户端工具 更新：2026-11-25 环境：MySQL 8.0

一屏速记合上笔记，这 5 条要能自己说出来

  1. 它只干一件事：把文本文件按行灌进一张已经存在的表。表名 = 去掉扩展名的文件名，命令行里没有「指定表名」这个参数。
  2. 默认由服务端读文件（路径必须落在 secure_file_priv 目录内，账号要有 FILE 权限）；--local 才改成客户端读。
  3. --local 要求服务端 local_infile=ON，8.0 默认是 OFF，不打开会报 ERROR 3950。
  4. 它是 mysqldump -T 的另一半：-T 拆出 .sql（建表）+ .txt（数据），恢复时先跑 .sql 建表，再用 mysqlimport 灌 .txt。
  5. source 是 mysql 客户端里的命令，读的是客户端本机文件；执行前必须先 USE 库名，否则脚本里没写库名的语句全部报错。

1. 它是 -T 的另一半

mysqldump -T 一条命令产出两个文件：emp.sql 存建表语句、emp.txt 存数据。恢复时也得两头走——SQL 归 mysql 客户端，数据归 mysqlimport。

2. 语法：文件名就是表名

课程给的语法只有一行，但里面藏着一个没写出来的约定——表名不由你指定，而是从文件名推出来：去掉扩展名，剩下的就是表名。

语法mysqlimport [options] db_name textfile1 [textfile2 ...]
课程示例mysqlimport -uroot -p2143 test /tmp/city.txt
两个符号别读错

-p2143 是「密码 = 2143」，紧贴 -p 没有空格；写成 -p 2143 会被当成两个参数，2143 会顶到 db_name 的位置上去。
test 是库名，不是表名。这一步等价于「先 USE test」。

3. 文件由谁读：默认在服务器上

这是 mysqlimport 最容易卡住的地方。它本质是 LOAD DATA INFILE 的命令行包装，默认由服务端读文件——你写的路径是数据库服务器上的路径，不是你本机的。

sql-- 先确认两个开关，比试错快
SHOW VARIABLES LIKE 'secure_file_priv';  -- 空值 = 禁止导入导出；NULL 也一样
SHOW VARIABLES LIKE 'local_infile';    -- 8.0 默认 OFF

-- 临时打开（重启失效）
SET GLOBAL local_infile = ON;
报错对照

ERROR 1290 (HY000): The MySQL server is running with the --secure-file-priv option → 没加 --local，而路径不在 secure_file_priv 目录里。要么把文件挪进去，要么加 --local。
ERROR 3950 (42000): Loading local data is disabled → 加了 --local，但服务端 local_infile 还是 OFF。
ERROR 1146 (42S02): Table 'test.city' doesn't exist → 表没建。mysqlimport 不负责建表。

这个「信任目录」的完整说明

secure_file_priv 的三种取值（目录 / NULL / 空字符串）、各平台默认值、四个常见报错和修改方式，都整理在 mysqldump · secure_file_priv 信任目录 那一节。这里只记一条结论：它约束的是「服务端读写文件」，加 --local 就完全不经过它。

4. 选项与实战

选项说明
-L / --local从客户端本机读文件，而不是服务端
-d / --delete导入前先清空目标表。用于覆盖式恢复，别对生产库随手加
-r / --replace遇到唯一键冲突，用新行替换旧行
-i / --ignore遇到唯一键冲突，跳过新行
--fields-terminated-by字段分隔符，默认 \t。与 mysqldump -T 的导出设置必须一致
--fields-enclosed-by
--fields-optionally-enclosed-by		字段包围符，CSV 一般用 "；后者表示「有就剥掉，没有也行」
--lines-terminated-by行结束符，Windows 生成的 CSV 常需 '\r\n'
--ignore-lines=N跳过前 N 行，CSV 去表头用
-c / --columns按给定列名顺序对应，文件列序与表列序不一致时用
--use-threads=N并行加载线程数，多个文件时才有意义
-f / --force某个文件出错也继续处理剩下的
 
shell# 与 mysqldump -T 配套：先建表，再灌数据
mysql -uroot -p123456 itcast < /var/lib/mysql-files/emp.sql
mysqlimport -uroot -p123456 itcast /var/lib/mysql-files/emp.txt

# 一个目录里全是「表名.txt」，一次灌完（覆盖式，慎用 --delete）
mysqlimport -uroot -p123456 --delete itcast /var/lib/mysql-files/*.txt

# CSV：分隔符、包围符、跳过表头，三项都要和导出时对齐
mysqlimport -uroot -p123456 --local \
  --fields-terminated-by=',' --fields-optionally-enclosed-by='"' \
  --ignore-lines=1 test /tmp/city.csv
分隔符不一致 = 整行塞进第一列

导入结果「第一列塞满了整行、其余列全是 NULL」，不是数据坏了，是分隔符没对上。mysqldump -T 默认用 TAB，所以导入时不要画蛇添足加 --fields-terminated-by=','；反过来，导出时用 --fields-terminated-by=','，导入也必须一致。

5. source：在客户端里跑 SQL 脚本

mysqlimport 只认数据文件。要导的是 .sql 脚本，就用 source——它是 mysql 客户端的内置命令，不是 SQL 语句。

语法source /root/xxxxx.sql

-- 等价简写（反斜杠 + 点）
\. /root/xxxxx.sql
mysql 会话mysql> USE itcast;              -- 单库备份里没有建库语句，必须先选库
Database changed
mysql> source /root/itcast.sql;
Query OK, 0 rows affected (0.00 sec)
Query OK, 1 row affected (0.01 sec)
...
mysql> SELECT COUNT(*) FROM emp;
source 的三个坑

① 忘了 USE。单库备份不带建库语句，直接 source 会一路报 ERROR 1046 (3D000): No database selected。
② 路径是本机的。source 由客户端读文件再发给服务端，所以 /root/xxxxx.sql 指的是你运行 mysql 命令那台机器的路径，不需要 FILE 权限，也不受 secure_file_priv 限制——这一点和 mysqlimport 的默认行为正好相反。
③ 出错不中断。交互式执行时，某条语句失败只打印一行错误，后面继续跑。恢复完必须自己核对：SELECT COUNT(*) FROM 表名，或数一下输出里 ERROR 的条数。

Windows 下的路径

反斜杠在 mysql 客户端里有转义含义，source C:\temp\a.sql 容易被吃掉字符。统一写成 source C:/temp/a.sql，最省事。

6. 按手里的文件选命令

一句话记住

.sql 是客户端读、逐条发给服务端执行，所以要么 source、要么 <；.txt 是服务端读（除非 --local），所以必须落在 secure_file_priv 里。方向搞反，报错码会提示你。

自测三问先自己答一遍，再点开对答案

Q1mysqlimport -uroot -p itcast /tmp/itcast.csv 报「表不存在」，可文件明明就叫 itcast？

表名取的是文件名（itcast.csv → 表 itcast），位置参数 itcast 是库名。mysqlimport 从不建表，必须先用 CREATE TABLE 建好同名表。

Q2不加 --local 报 ERROR 1290，加上就通了，为什么？

不加时由服务端读文件，路径必须在 secure_file_priv 指定目录内（该变量为 NULL 时完全禁止）。--local 改成客户端读、再通过网络送过去，绕开这个目录限制，但要 local_infile=ON。

Q3用 source 导入脚本报 No database selected，脚本本身没问题吧？

脚本可能只写了 CREATE TABLE t ... 这类不带库名的语句。source 只是把文件内容当 SQL 逐条执行，不会自动切库——进客户端后先 USE itcast; 再 source，或在脚本开头自己写 USE。
